# 敌人负责人任务说明（小怪 + Boss）

## 1. 目标
在 1-2 周内交付稳定的敌人与刷怪系统：
- 小怪战斗节奏成立（巡逻、追击、攻击、受击、死亡）
- Boss 至少 2 阶段行为
- 敌人强度可被时间难度系统统一放大

## 2. 你拥有的模块
- 敌人抽象与AI：Assets/Scripts/Enemies/EnemyBase.cs
- 小怪实现：Assets/Scripts/Enemies/MinionEnemy.cs
- Boss 实现：Assets/Scripts/Enemies/BossEnemy.cs
- 生成与复活：Assets/Scripts/Systems/EnemySpawner.cs
- 血条逻辑（共用）：Assets/Scripts/UI/HealthBarCanvas.cs

## 3. 本线任务清单

### Day 1-2：敌人状态完善
- 将 EnemyBase 行为收敛为最小状态：Patrol/Chase/Attack/Hit/Dead
- 明确受击后硬直窗口，避免与移动逻辑冲突
- 统一敌人朝向与碰撞行为，避免翻转导致判定错位

### Day 3-4：Boss 两阶段
- Phase 1：基础追击 + 普通攻击/冲刺
- Phase 2：血量阈值触发后提升攻击节奏或新增技能
- Boss 死亡时抛出统一事件，供流程与掉落系统消费

### Day 5-6：刷怪与难度接入
- EnemySpawner 接入难度快照（血量、伤害、刷怪权重倍率）
- 统一新刷敌人的初始化流程（吃到当前难度）
- 保留现有复活机制作为兜底

### Day 7-8：联调修正
- 与主角线联调命中反馈、击退、招架成功后的敌人响应
- 与道具线联调掉落触发、击杀触发事件
- 修复空刷怪、死后重复触发事件、Boss 状态切换异常

## 4. 你必须提供的接口能力
- 受击入口：ReceiveHit(in CombatContext ctx)
- 死亡事件：OnEnemyDied(GameObject enemy, CombatContext killingBlow)
- 难度注入：ApplyDifficulty(DifficultySnapshot snapshot)
- 敌人类型标识：GetEnemyTypeId()（用于掉落表与统计）

## 5. 完成标准（DoD）
- 小怪和 Boss 都能稳定完成一整套战斗循环
- 新刷出的敌人始终读取当前难度倍率
- 死亡事件只触发一次，且能被掉落系统稳定消费
- 长时间运行（10 分钟）无明显刷怪中断

## 6. 非目标（先不做）
- 复杂群体协同行为（战术包抄）
- 超过 2 阶段的 Boss 机制
- 大规模敌人种类扩展

## 7. 已提供首个实现（可直接参考）
- 敌人基类接入 CombatContext：Assets/Scripts/Enemies/EnemyBase.cs
- 小怪主动攻击基线：Assets/Scripts/Enemies/MinionEnemy.cs
- Boss 受击接口对齐：Assets/Scripts/Enemies/BossEnemy.cs

已实现内容：
- MinionEnemy 新增主动近战攻击（strikeRange/strikeCooldown/strikeDamage）
- 小怪攻击统一构建 CombatContext 并走 Damageable 结算
- EnemyBase 在死亡时统一广播 BattleEvents.OnEnemyDied
- EnemyBase 实现 IEnemyTypeProvider，供掉落系统按敌人类型匹配

验证步骤（首版）：
1. 在小怪预制体保持 MinionEnemy 组件启用 useActiveStrike。
2. 接近玩家后应按冷却主动攻击，而非纯接触伤害。
3. 敌人死亡时应触发 OnEnemyDied（供掉落服务消费）。
